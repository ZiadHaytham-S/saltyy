# المنتجات الرقمية وتصميم المتجر — 13 أكتوبر 2026

توسعة وافق عليها صاحب المشروع: منتجات ملموسة ورقمية، تسليم رقمي بعد تأكيد التاجر لاستلام المبلغ، وعشرة ثيمات محلية قابلة للتخصيص. PayPal والتحويل البنكي وتكاملات الدفع مؤجلة؛ تأكيد المبلغ ليس عملية دفع ولا يتحقق من بنك.

## المنتجات والطلبات

- المنتجات السابقة تعتبر PHYSICAL بدون تغيير أسعارها أو المخزون. المنتج الرقمي يختار DIGITAL ورابط تسليم HTTPS وخيار التسليم التلقائي. الكمية تمثل عدد التراخيص المتاحة؛ معاملات المخزون تمنع تجاوزها كما في المنتجات الملموسة.
- Backend يحدد requiresShipping من المنتجات الفعلية، وليس قيمة يرسلها العميل. الطلب الرقمي بالكامل بلا محافظة أو مدينة أو عنوان، ورسوم شحنه صفر حتى لو لم يضبط التاجر الشحن. السلة المختلطة تحتاج عنوانًا ورسوم الشحن الثابتة.
- الطلب الذي يحتوي على رقمي يستخدم MANUAL؛ الطلب الملموس فقط يحتفظ بـ COD. لا يتم عرض وسيلة تحويل أو حساب بنكي وهمي. يتواصل العميل مع التاجر عبر بيانات التواصل العامة التي اختار نشرها.
- Order يحفظ Snapshot لنوع المنتج ورابط التسليم واختيار التلقائي وقت الشراء. تعديل المنتج أو أرشفته لاحقًا لا يغيّر التسليم السابق. الأسعار والمخزون وIdempotency تبقى ضمن نفس MongoDB Transaction.
- صاحب المتجر وحده يؤكد استلام كامل إجمالي الطلب. نسجل PAID وpaidAt وpaidBy ونزيد version داخل Transaction. التكرار لا يعيد العملية. الطلب الملغي لا يمكن تأكيده. إلغاء الرقمي المدفوع مرفوض حتى اعتماد استرداد المبالغ.
- رابط التسليم لا يظهر في Public Product أو Receipt أو Merchant Order DTO. Endpoint POST digital-delivery يطلب Receipt capability عشوائية، ويتحقق من المتجر والمنتج داخل الطلب والدفع والصلاحية قبل إظهار الرابط. التلقائي متاح فور التأكيد؛ غير التلقائي يحتاج زر إتاحة التسليم من التاجر بعد التأكيد.
- الوصول عبر صفحة التأكيد الخاصة يستمر سبعة أيام، وفق Receipt الموجودة. العميل يحتفظ بالصفحة في نفس المتصفح ويضغط تحديث حالة التسليم. لا يتم إرسال رسالة بريد تسليم في هذه التوسعة.
- التسليم الحالي برابط HTTPS يحدده التاجر. الوصول إلى الرابط داخل Sallty محمي؛ بعد حصول المشتري عليه، خصوصية الملف الخارجي ومنع مشاركة رابط مزوده ليست مسؤولية تحقق Sallty. لم نضف Upload ملفات رقمية مدفوعة أو حماية DRM أو حسابات عملاء.

## الثيمات والمحرّر

صفحة `/dashboard/design` تعرض Sallty وMinimal وBoutique وOasis وStudio وLuxury وMarket وTech وPlayful وDigital. لكل ثيم طابع بصري، والقواعد معزولة تحت StoreShell دون تغيير لوحة التاجر أو متجر آخر.

التاجر يعدل اللون والخط والأعمدة وشكل البطاقات، العنوان والوصف والإعلان والشعار والصورة الرئيسية، وإظهار Hero والتصنيفات وموضع الفيديو قبل المنتجات أو بعدها. Preview تستخدم منتجات المتجر وصوره الفعلية؛ الحفظ هو الذي يطبّق الإعدادات للعامة. لا يوجد محرر HTML أو CSS أو JavaScript حر.

صور الشعار والبنر تستخدم Storage Adapter ورفع الصور الحالي؛ Backend يتحقق من ملكيتها ويمنع حذف الصورة المرتبطة بالتصميم. Public branding endpoint لا يعرض صورة لمجرد معرفة ID؛ يلزم أن تكون مرتبطة بتصميم المتجر المطلوب.

بيانات WhatsApp وFacebook وInstagram وTikTok وLinkedIn وSnapchat والهاتف والبريد والعنوان مخصصة للنشر العام وبشكل اختياري؛ بيانات حساب التاجر لا تستخدم بديلًا تلقائيًا. الروابط HTTPS فقط؛ أرقام الهاتف وWhatsApp بالصيغة الدولية.

الفيديو: YouTube عبر youtube-nocookie مع التحقق من host وVideo ID، أو رابط HTTPS لفيديو مخصص، أو MP4 مرفوع محليًا. MP4 حدّه 20 MB، عشرة فيديوهات و100 MB لكل متجر، مع Rate Limit وOrigin وCSRF والتحقق من حاوية الملف وMIME والامتداد والحجم. لا يوجد transcoding أو تحويل codecs؛ قابلية تشغيل codec الفعلي تحتاج فيديو حقيقي على متصفحات المستخدمين. الفيديو العام مرتبط بالتصميم المنشور فقط، ويدعم Range requests. حذف الفيديو المستخدم ممنوع حتى فصله وحفظ التصميم.

## التشغيل والتجربة

شغّل MongoDB عبر `pnpm db:start` ثم `pnpm dev` في Terminal أخرى. المنتجات من `/dashboard/products/new`، التصميم من `/dashboard/design`، والطلبات من `/dashboard/orders`.

جرّب طلبًا رقميًا من نافذة خاصة، واحتفظ بصفحة التأكيد. من Dashboard افتح الطلب، اضغط تأكيد استلام المبلغ ثم أكد أنك استلمته كاملًا. عُد لصفحة العميل وحدّث حالة التسليم؛ يظهر زر الاستلام للتلقائي. للتسليم اليدوي، اضغط إتاحة التسليم في تفاصيل الطلب.

الاختبارات: Unit للتحقق من الروابط والثيمات وحاوية MP4 وRanges، Integration على replica set لعزل المتاجر وعدم التسليم قبل الدفع وثبات Snapshot والتكرار والسلة المختلطة وملكية الصور والفيديو، ومتصفح حقيقي لإنشاء منتج رقمي وشراء بلا عنوان وتأكيد المبلغ والاستلام وتخصيص ثيم وحفظه.

التجربة اليدوية المتبقية: تشغيل MP4 حقيقي وYouTube على الموبايل، اختيار الهوية والألوان المناسبة للمحتوى الحقيقي، ومراجعة جودة روابط التسليم الخارجية. هذه التوسعة لا تفعّل نشرًا عامًا أو DNS أو خدمات مدفوعة أو المرحلة التالية تلقائيًا.
