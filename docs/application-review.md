# مراجعة رحلة التاجر وجاهزية السوق — 11 أكتوبر 2026

ده سجل المراجعة قبل Phase 5. المتجر العام اتنفذ بعدها بنطاق العرض فقط؛ الحالة الحالية في [storefront.md](storefront.md). Cart/Checkout/Orders واستعادة كلمة المرور وتجهيز النشر لسه ناقصين.

صاحب المشروع أبلغ إن الصفحة الرئيسية بتعرض تسجيل حساب وهو مسجل، وإن حفظ الاسم مش بيوضح الخطوة التالية. المراجعة دي تصحيح للرحلة الموجودة داخل Phase 4، ومش بداية Phase 5.

## المشاكل والتصحيح

- الصفحة الرئيسية مكنتش بتقرأ Session؛ كانت بتعرض نفس أزرار التسجيل للكل. دلوقتي المسجل المؤكد يدخل Dashboard، وغير المؤكد يدخل Verify Email، والزائر يشوف الإمكانيات المتاحة فعلًا.
- فورم الاسم كان بيعمل تنقل لنفس Dashboard بعد الحفظ. مسار Edit Store دلوقتي يعرض تأكيد ثابت ويحدث بيانات الصفحة بس؛ مفيش إعادة تسجيل أو تحويل لصفحة تانية. حفظ الاسم معناه تعديل الاسم، مش فتح ميزة جديدة.
- Dashboard كانت بتكرر خطوات التسجيل وتعرض تعديل الاسم كأنه المهمة الرئيسية. استبدلنا ده بأعداد حقيقية للـ Active/Draft/Archived والتصنيفات من API؛ كل عدد لينك لقائمته. فيه إضافة منتج وإدارة تصنيفات وإرشاد لأول منتج لو الكتالوج فاضي.
- تعديل الاسم في قسم منفصل بيتفتح عند الحاجة. Slug معرّف المتجر حاليًا، مش رابط عام للعملاء.
- تفاصيل Phase والسيرفر والداتا بيز و«تطوير محلي من غير اشتراكات» اتشالت من واجهة العميل؛ Health/Ready endpoints لسه للفحص. الوصف يشرح إدارة الكتالوج من غير عرض الطلبات كميزة شغالة.
- فورم الحساب والمتجر بيستنى Hydration، يعني ربط JavaScript بأحداث الحقول، علشان التعديل السريع ميتفقدش وقت تفعيل الصفحة.

## التحقق

النتيجة النهائية: `build` و`lint` و`format:check` نجحوا، ومعاهم 8 Unit Tests و29 نتيجة في Integration Tests على MongoDB replica set، ورحلة `test:web` في Edge الحقيقي على نسخة production. اتراجعت صور Dashboard للموبايل؛ زر إضافة المنتج ورسالة حفظ الاسم ظاهرين. اختيار «بدون تصنيف» في فورم المنتج بقى له قيمة UI صريحة بتتحول لـ `null` عند إرسال الـ API؛ الاختبار بيتأكد إن الاختيار يفضل ثابت بعد تغيير الحالة، وإن التصنيف اتفصل فعلًا في الداتا بيز.

`scripts/auth-web-test.mjs` اتحدث لاختبار الصفحة الرئيسية بجلسة غير مؤكدة ومؤكدة، ورحلة متصفح فعلية: فتح `/` بعد الدخول ينتهي في Dashboard، مفيش Register CTA، الكتالوج الفاضي له دعوة واضحة، حفظ الاسم يحدث العنوان ويظهر تأكيد نجاح، وإضافة Active تحدث عداد Dashboard. اختبارات المنتجات والتصنيفات والصور والخروج والدخول لسه في الرحلة. الاختبارات على قاعدة مؤقتة وSMTP محلي؛ مفيش إرسال جديد لحسابات حقيقية.

`scripts/smoke.mjs` اتحدث لفحص الصفحة العامة والـ API بدل اشتراط عرض حالة السيرفر في Marketing. السكريبت محتاج ports 3000/4000 فاضيين؛ متشغّلش في المراجعة دي لأن dev شغال عليهم. `test:web` اختبر نسخة production على ports منفصلة؛ مفيش إيقاف لـ dev بتاعك.

## الملفات والتجربة

- `apps/web/src/app/page.tsx`: تمييز المسجل عن الزائر وعرض تعريف واضح بالإمكانيات.
- `apps/web/src/app/dashboard/page.tsx`: ملخص حقيقي وروابط الشغل وتعديل الاسم عند الحاجة.
- `apps/web/src/components/merchant-form.tsx`: تأكيد حفظ الاسم من غير تنقل غير ضروري، وجاهزية التفاعل بعد Hydration.
- `scripts/auth-web-test.mjs`: اختبارات الملاحظات اللي بلغ عنها صاحب المشروع مع الرحلة الحالية.
- `scripts/smoke.mjs`: توقعات الصفحة العامة بعد إزالة تفاصيل التطوير.

1. وأنت مسجل افتح `http://127.0.0.1:3000/`؛ تدخل Dashboard مباشرة.
2. افتح «تعديل اسم المتجر»، غيّره واضغط «حفظ اسم المتجر». العنوان يتحدث ومعاه رسالة نجاح، وتفضل في Dashboard.
3. اضغط «إضافة منتج» أو «إضافة أول منتج». احفظ Active وارجع Dashboard؛ العداد يتحدث من بيانات متجرك.
4. بعد Logout، الصفحة الرئيسية تعرض إنشاء حساب للزائر.

الخطوة التالية قرار منفصل: الموافقة على Phase 5 لإكمال رحلة العميل والطلب، ثم تجهيز النشر قبل الاستخدام التجاري.
