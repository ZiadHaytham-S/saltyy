# محرّر المتجر البصري — 14 أكتوبر 2026

توسعة معتمدة للتصميم الحالي: يستطيع صاحب المتجر تعديل هويته ومحتواه ومعاينته بنفسه. لا توجد خدمة مدفوعة أو تكامل جديد، ولا صلاحيات Staff أو تغيير DNS أو نشر خارجي.

## تجربة التاجر

صفحة مستقلة `/dashboard/design/editor` تعرض المحرّر بملء مساحة المتصفح، فوق تخطيط Dashboard. المتجر يستخدم عرضه الطبيعي دون `scale` أو مربع معاينة مصغّر، مع شريط الحفظ في الأعلى. أدوات التعديل والثيمات تفتح في لوحة جانبية عند الضغط على قسم أو زر الأدوات، ويمكن إغلاقها لرؤية المتجر كاملًا. على الهاتف تتسع اللوحة بعرض الشاشة. المعاينة تتغير فورًا، لكن العملاء لا يرون التغيير قبل «حفظ التصميم وتطبيقه». «حفظ مسودة» يبقى خاصًا بصاحب المتجر. زر الرجوع يعيد المستخدم إلى صفحة التصميم المعتادة.

من `/dashboard/design` توجد أدوات الحفظ والنشر، اختيار الثيمات العشرة، قائمة الأقسام، وإعداداتها بجوار معاينة فورية. الضغط على القسم داخل المعاينة يختاره ويفتح إعداداته. يمكن اختيار عرض كمبيوتر أو موبايل. اختيار الثيمات في قائمة قابلة للفتح حتى لا يزاحم المحرّر.

المعاينة الافتراضية تعرض الموقع الفعلي داخل iframe محمي في `/preview/store`، بقالب StoreFrame نفسه وHeader وFooter وبطاقات المنتجات الفعلية. تغييرات الهوية والأقسام تنتقل محليًا عبر postMessage وتظهر فورًا دون طلب حفظ. كل طرف يتحقق من origin وsource، والمعاينة تتحقق من Zod وتختار الوسائط عبر endpoints التاجر المحمية. النقر على القسم يختاره في أدوات التحرير. سياسة frame-ancestors وX-Frame-Options تقصر التضمين على نفس الموقع؛ sandbox يمنع تقديم النماذج والتنقلات غير اللازمة. يوجد اختيار معاينة سريعة بديلة. تغيير المظهر واللغة يزامن المعاينة دون مسح إعدادات المحرّر.

الأقسام المتاحة: Hero، المنتجات، التصنيفات، إعلان ترويجي بصورة وزر، نص تعريفي، وفيديو. يمكن إضافة الإعلان والنص والفيديو أكثر من مرة، مع حد 20 قسمًا. Hero والمنتجات والتصنيفات لا تتكرر. الترتيب بأسهم لأعلى ولأسفل تعمل بالموبايل والكيبورد، والإظهار والإخفاء والحذف من إعدادات القسم. حذف القسم لا يحذف المنتج أو الملف نفسه.

يمكن تعديل عناوين الأقسام والمحتوى والصور والفيديو والروابط والمحاذاة. الإعلان والنص لهما ألوان مستقلة. الهوية العامة تشمل الخلفية والنص واللون الأساسي والخط والمسافات وشكل بطاقات المنتجات وعدد الأعمدة، مع الشعار والإعلان العام وبيانات التواصل السابقة. الخطوط المتاحة Cairo وخط النظام؛ لا يتم تنزيل خطوط خارجية.

## المسودة والنشر

- التعديل يظهر فورًا في المعاينة داخل المحرّر؛ لا يرسل طلبًا لكل ضغطة مفتاح.
- «حفظ مسودة» يحفظ designDraft في MongoDB دون تغيير design المنشور. المسودة قد تحتوي إعداد فيديو غير مكتمل؛ الروابط الخطرة والمعرفات غير الصحيحة تظل مرفوضة.
- «حفظ التصميم وتطبيقه» يتحقق من اكتمال الإعدادات المرئية وينشرها. إعداد فيديو مخفي أو غير مستخدم لا يمنع نشر الأقسام المكتملة.
- «استعادة آخر حفظ» يعيد الحالة المحفوظة الأخيرة داخل المحرّر. يوجد مؤشر تغييرات غير محفوظة وتنبيه المتصفح عند إغلاقه؛ لا يوجد Autosave أو Undo متعدد الخطوات. التنبيه لا يعترض كل تنقل داخلي في Next.js.
- المعاينة الخاصة `/dashboard/design/preview` تستخدم نفس صفحة المتجر الفعلية بآخر مسودة محفوظة وبيانات المنتجات الحقيقية. تتطلب جلسة صاحب متجر موثق وتختار متجره من الجلسة؛ لا تقبل Store ID من الرابط. التعديلات التي لم تُحفظ تظهر في معاينة المحرّر فقط.

## البنية والأمان

`store-page.tsx` قالب الصفحة المشتركة بين المتجر العام والمعاينة الخاصة. `store-sections.tsx` يرسم ترتيب الأقسام نفسه في المحرّر والمتجر؛ لا يستخدم HTML أو JavaScript خامًا. النصوص تعرض كنص، وروابط الأزرار والفيديو HTTPS فقط، وYouTube مقيد بالمضيف ومعرف الفيديو.

StoreFrame واجهة مشتركة قابلة للرسم في Server Components والمتصفح. Server Components تمرر بطاقات المنتجات والفلاتر الفعلية إلى المعاينة؛ لا نعيد منطق MongoDB أو صلاحيات المنتجات في المتصفح. بيانات المنتج الرقمي الخاصة بالتسليم لا تدخل رسائل المعاينة.

NestJS يتحقق من ملكية جميع الصور والفيديوهات داخل الأقسام والمسودة، مع version لمنع الكتابة فوق تعديل أحدث. MongoDB Transaction تضم حفظ التصميم ومراجعة الوسائط. يمنع حذف ملفات مستخدمة في التصميم المنشور أو المسودة حتى فصلها وحفظ التعديل. public DTO لا يحتوي المسودة أو الأقسام المخفية أو معرفات الوسائط الداخلية. public asset endpoint يتحقق من الارتباط بالمتجر المنشور، وليس ID فقط.

التصميم القديم يستمر حتى اختيار المحرّر الجديد وحفظه. customLayout يميز التصميم المخصص حتى عند إفراغ كل أقسامه؛ لا تعود الأقسام الافتراضية تلقائيًا. إخفاء قسم المنتجات يغيّر العرض فقط؛ المنتج Active يظل متاحًا عبر رابط تفاصيله وPublic API، ولا يحوله إلى Draft.

حد JSON للتصميم وحده 256 KB لاستيعاب الأقسام. طلبات الحسابات وبقية JSON تستمر عند 16 KB. رفع الصور 5 MB والأنواع JPEG/PNG/WebP؛ الفيديو MP4 حتى 20 MB، وبقية حصص التخزين السابقة مستمرة. الفيديو لا يعاد ترميزه؛ تشغيل Codec وفيديو YouTube على أجهزة حقيقية يحتاج تجربة يدوية.

## التحقق

اختبارات عقود البيانات تغطي الحدود والمعرفات المكررة والروابط الخطرة وعدم اكتمال المسودة. Integration على replica set تختبر عدم تسرب المسودة، النشر والترتيب وإخفاء المحتوى وملكية الوسائط وحد JSON، مع اختبارات الحسابات والطلبات القائمة. اختبار المتصفح ينشئ إعلانًا ويعاينه خاصًا ثم ينشره وينقله ويخفيه، ويتحقق من RTL والموبايل والكمبيوتر ومنع المعاينة للمستخدم غير المسجل.

هذه أدوات تخصيص للمحتوى والهوية والأقسام المدعومة؛ إضافة وظائف أعمال جديدة أو صفحات مستقلة أو محرر كود حر أو تكاملات خارجية تحتاج نطاقًا منفصلًا. يمكن تطوير أنواع الأقسام لاحقًا عبر العقود والرسم المشترك، دون نسخ متجر منفصل لكل تاجر.
