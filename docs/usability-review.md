# مراجعة سهولة الاستخدام — 12 أكتوبر 2026

المراجعة ضمن الواجهات الحالية حتى Phase 6، وليست بدءًا لـPhase 7 أو إضافة مزايا البيع المؤجلة.

المشكلة: القائمة كانت تعرض أقسامًا غير منفذة كثيرة بجانب الأدوات المتاحة، وصفحة البداية لا تشرح الصلة بين المنتجات والشحن وتجربة العميل والطلبات. التصميم استخدم خلفيات متقاربة قللت الفصل البصري.

التعديل: صفحة الملخص تعرض خطوات التجهيز حسب المنتجات النشطة وإعداد الشحن الحقيقي، ثم الطلبات المعلقة الفعلية. لا توجد أرقام مبيعات مختلقة. حالة تجربة العميل لا تُعلَّم مكتملة تلقائيًا بمجرد فتح رابط. الدول الأخرى ما زالت تدعم الحسابات والكتالوج؛ Checkout الحالية مصرية EGP فقط.

القائمة تعرض الأقسام المتاحة مباشرة وتجمع الأقسام المؤجلة في «مزايا مخطط لها». صفحة `/dashboard/help` تشرح إضافة منتج نشط، ضبط الشحن، تجربة Checkout، ومراجعة الطلب وإلغاء طلب التجربة لاستعادة المخزون. هذه الطلبات حقيقية، وليست بيئة دفع أو شحن تجريبية وهمية.

هوية Sallty زرقاء مع أسطح بيضاء في الوضع الفاتح وأسطح داكنة متباينة في الوضع الداكن. سلة مرجع عام لفكرة تنظيم أدوات التاجر، وليس نسخًا للتصميم أو ادعاء الاطلاع على لوحة خاصة؛ الرابط العام يعتمد على JavaScript ولم يوفّر محتوى لوحة قابلاً للمراجعة النصية.

الملفات المهمة: `apps/web/src/app/dashboard/page.tsx`، `dashboard/help/page.tsx`، `components/dashboard-sidebar.tsx`، `components/merchant-shell.tsx` و`app/globals.css`. لا تغيير في Authentication أو صلاحيات NestJS أو MongoDB أو DNS.

التجربة: افتح Dashboard ثم «دليل الاستخدام». اتبع الخطوات في نافذة خاصة للمتجر، وبعد وصول الطلب افتح الطلبات وألغِ طلب التجربة قبل الشحن. تحقق من الموبايل والعربية/الإنجليزية وDark/Light.

المراجعة كشفت أيضًا سباقًا في الانتقال الداخلي إلى تأكيد الطلب: App Router قد يركّب الصفحة قبل إضافة URL fragment، فتقرأ إثبات تأكيد فارغًا. Checkout وRecover الآن يحفظان Receipt Token في sessionStorage الخاصة بالمتجر قبل الانتقال؛ صفحة التأكيد لديها هذا المسار الاحتياطي بالفعل. هذا إثبات عرض رقم وحالة الطلب فقط، وليس Merchant Session أو بيانات عميل. قاعدة البيانات ومنطق إنشاء الطلب لم يتغيرا.

نتائج المراجعة: TypeScript وLint وBuild وFormatting نجحوا، ورحلة Edge الكاملة نجحت بعد الإصلاح. الاختبار يشمل فتح الدليل، توجيه المتجر الفارغ لإضافة منتج، اكتمال الخطوة بعد نشره، وحفظ إثبات التأكيد أثناء التنقل؛ ويشمل الحسابات واستعادة كلمة المرور والكتالوج والطلبات واسترجاع طلب بعد ضياع الرد، مع بيانات مؤقتة وSMTP محلي. لم تُعد Unit وIntegration المنفصلة في هذه المراجعة؛ لا تغييرات Backend أو قواعد البيانات. الاختبار لا يغني عن التجربة على أجهزة فعلية أو مراجعة جاهزية النشر.
